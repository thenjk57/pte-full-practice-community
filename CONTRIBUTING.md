# Contributing

Open an issue describing the problem, or send a pull request with a focused change. Include steps to reproduce a bug and explain how you checked the fix.

## Development

Follow the setup in [README.md](README.md) and run `npm test` before submitting code changes. Use a separate checkout and fresh database for tests that submit attempts or reseed content; those operations can change or clear practice history.

Check timing and exam-format changes against published Pearson guidance. Link the source and distinguish official requirements from our simulator's approximations. Do not promise official scores or guaranteed outcomes.

## Practice content

Submit original questions or material with a license that permits redistribution. Include source URLs, attribution and license terms. Keep CC BY-SA attribution and share-alike terms with adapted Wikipedia material. Do not submit copied commercial question banks or screenshots from paid practice accounts.

## Privacy

Keep passwords, tokens, environment files, databases, recordings, personal score reports and account screenshots out of commits and issue attachments. Use fictional examples when reproducing a bug. Check the staged diff and file list before pushing.

If you discover exposed credentials or personal information, report it privately through GitHub's vulnerability reporting feature when available. Do not include the sensitive value in a public issue.

Project code contributions use the ISC license; third-party material retains its original terms.
